# VPS4構築に関する作業レポート(~10/6 10:40)
　
## アカウント管理
今まで、Ubuntu（管理者）で全ての作業を行っていたが、VPN接続不可に備えて以下のようにアカウントを分離した。

### 管理アカウント
ユーザ名やディレクトリはそのまま変更せずに、Ubuntuを管理アカウントとした。
ただし、認証について今まで公開鍵認証だったが、使っているMacBookのIPアドレスからのみパスワード認証できるようにした。

### 作業アカウント
作業用アカウントを作成した。
こちらに関しては、VPN経由で公開鍵認証のみに制限した。
また、こちらのアカウントでもSudoを使用できるようにした。

## ファイアウォール
UFWを有効化し、上で紹介したような認証に使用するポート・ハニーポットで使用するポートを許可した。

## Dionaea
ハニーポットに関しては、第一段階と特に変更はない。

## Suricata
Suricataを導入した。
eth0に対してAF_Socketで監視する構成にした。
また、VPS４のメモリが2GBだったので、Systemdで以下のように設定した。
- memory_high = 1200M
- memory_max = 1500M

こちらに関しては、完了時点でSuricataは自動起動が有効で、再起動0回・エラーなしで動いていた。

### オフロード設定
パケット解析の精度を維持するために、eth0で以下のオフロード機能を無効化した。
- TX checksum
- Scatter-gather
- tcp segmentation 
- Generic segmentation
- Generic receive

再起動後のこの設定を適用した。

## ログ正規化
SuricataのEVE JSON原本をLinuxWSの共通スキーマ（1.0）に適合するNDJSONへ変換する正規化処理を実装した。

正規化サービスは専用のautosoclogユーザーで実行し、必要なログと状態ディレクトリ以外への書き込みを制限した。

### 対象データ
対象のデータセットは以下の4つとした。
- suricata.alert
- suricata.anomaly
- suricata.flow
- suricata.stats

### データの最小化
Wazuhへ送信する正規化ログには、分析に必要な許可済データのみを格納する。

以下の情報は正規化ログに含めないとした。
- パケット本文
- ペイロード本文
- HTTP本文
- DNS応答内容
- 認証情報
- Cookie
- パスワード
- マルウェア本体
- その他の許可されていないEVEフィールド

送信元・宛先アドレスなど、セッション分析に必要なネットワークメタデータはrestricted_internalとして取り扱う。

## Wazuh連携
VPS4はLinuxWS上のWazuhManagerへVPN経由で接続し、次の識別情報で登録した。
- AgentID：002
- Agent名：Vps4-iot-honeypot
- 状態：Active

古いDockerコンテナIDを参照していたlocalfile設定は削除し、正規化ログのみを収集対象とした。
