# Wazuh ManagerへのVPS2〜VPS4 Agent接続およびログ収集基盤構築 作業報告書

## 1. 作業目的

本作業では、Autonomous AI-SOC Systemsの基盤構築の一環として、複数のハニーポット用VPSからWazuh Managerへログを集約する環境を整備した。

Wazuh ManagerをVPS1に配置し、VPS2〜VPS4にWazuh Agentを導入することで、各ハニーポットのログを中央のManagerへ転送し、後続の検知ルール作成・アラート化・AI-SOC連携に利用できる状態を目指した。

## 2. 構成

今回の構成は以下の通りである。

| VPS  | 役割                       | 主な用途              |
| ---- | ------------------------ | ----------------- |
| VPS1 | Wazuh Manager            | 各Agentからのログ受信・集約  |
| VPS2 | Wazuh Agent + Web系ハニーポット | Dionaea Webハニーポット |
| VPS3 | Wazuh Agent + DB系ハニーポット  | Dionaea DBハニーポット  |
| VPS4 | Wazuh Agent + IoT系ハニーポット | IoTハニーポット         |

通信にはTailscaleを利用し、Managerの接続先IPを設定した。

Wazuh AgentとManager間の通信ポートは以下である。

```text
TCP 1514
```

WazuhのバージョンはManagerに合わせ、Agent側も以下で統一した。

```text
wazuh-agent 4.9.2-1
```

## 3. VPS2〜VPS4のAgent接続作業

各VPSでは、Wazuh Agentを導入し、VPS1のManagerへ接続する設定を行った。

Agent側の `/var/ossec/etc/ossec.conf` には、以下のようにManager接続先を設定した。

```xml
<client>
  <server>
    <address>100.xx.xx.xx</address>
    <port>1514</port>
    <protocol>tcp</protocol>
  </server>
</client>
```

Agentの登録には、VPS1上の `manage_agents` を使用した。
Manager側でAgentを追加し、発行されたキーを各VPS側でインポートした。

```bash
sudo /var/ossec/bin/manage_agents -i '<Managerで抽出したAgentキー>'
```

その後、各Agentの状態をVPS1で確認した。

```bash
sudo /var/ossec/bin/agent_control -l
```

最終的に、VPS2〜VPS4のAgentはすべて `Active` となり、VPS1のWazuh Managerとの接続が完了した。

## 4. 発生した問題と対応

### 4.1 Agent名の重複による接続失敗

VPS2では、Agent登録時に以下のエラーが発生した。

```text
ERROR: Duplicate agent name: server-707001-012 (from manager)
ERROR: Unable to add agent (from manager)
```

これは、Manager側に同じAgent名が既に登録されていたため、Agentが新規登録を行えなかったことが原因である。

対応として、Manager側のAgent登録状態を確認し、不要なAgent登録を整理した。また、最終的に有効なAgent IDを確認し、そのIDを基準に接続状態を確認した。

### 4.2 `queue/rids` の権限不整合

VPS2では、キー取得後に以下のエラーが発生した。

```text
CRITICAL: Could not open file 'queue/rids/008' due to [(13)-(Permission denied)].
```

原因は、`/var/ossec/queue/rids` 周辺の所有者・権限が、Wazuh Agentの実行ユーザーと一致していなかったことである。

確認時には以下のように所有者が混在していた。

```text
/var/ossec/queue        root:wazuh
/var/ossec/queue/rids   root:ossec
/var/ossec/etc/client.keys   wazuh:wazuh
```

この環境では `wazuh` ユーザー・グループでAgentが動作していたため、以下のように権限を修正した。

```bash
sudo chown root:wazuh /var/ossec/queue
sudo chmod 750 /var/ossec/queue

sudo chown -R wazuh:wazuh /var/ossec/queue/rids
sudo chmod 750 /var/ossec/queue/rids
sudo chmod 660 /var/ossec/queue/rids/<Agent_ID>

sudo chown wazuh:wazuh /var/ossec/etc/client.keys
sudo chmod 640 /var/ossec/etc/client.keys
```

この対応により、Agentが正常にManagerへ接続できるようになった。

### 4.3 VPS3のディスク容量不足

VPS3では、Wazuh Agentのインストール時に以下のエラーが発生した。

```text
No space left on device
```

ディスク使用状況を確認したところ、`/home/ubuntu/honeypot/dionaea/logs/dionaea/dionaea.log` が約34GBまで肥大化しており、ルートディスクを圧迫していた。

```text
/home/ubuntu/honeypot/dionaea/logs/dionaea/dionaea.log  34G
```

対応として、必要な末尾ログを保存した上で、元ログを空にした。

```bash
sudo tail -n 1000 /home/ubuntu/honeypot/dionaea/logs/dionaea/dionaea.log > ~/dionaea_last_1000.log
sudo truncate -s 0 /home/ubuntu/honeypot/dionaea/logs/dionaea/dionaea.log
```

その後、APTのキャッシュとリストを整理し、Wazuh Agentのインストールを再実行した。

```bash
sudo rm -rf /var/lib/apt/lists/*
sudo apt clean
sudo apt update
sudo apt install -y wazuh-agent=4.9.2-1
sudo apt-mark hold wazuh-agent
```

### 4.4 Wazuhリポジトリ未登録

VPS3では、当初以下のエラーが発生した。

```text
E: Unable to locate package wazuh-agent
```

これはWazuhのAPTリポジトリが登録されていなかったことが原因であった。

対応として、WazuhのGPGキーとAPTリポジトリを追加した。

```bash
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | \
sudo gpg --no-default-keyring \
--keyring gnupg-ring:/usr/share/keyrings/wazuh.gpg \
--import

sudo chmod 644 /usr/share/keyrings/wazuh.gpg

echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | \
sudo tee /etc/apt/sources.list.d/wazuh.list

sudo apt update
```

その後、`wazuh-agent=4.9.2-1` を正常にインストールできた。

### 4.5 `ossec.conf` のXML構文エラー

VPS3では、DockerログをWazuh Agentに読ませるために `<localfile>` を追加した際、以下のエラーが発生した。

```text
wazuh-execd: ERROR: (1226): Error reading XML file 'etc/ossec.conf':  (line 0).
```

原因は、`ossec.conf` のXML構文が崩れていたことである。特に、`<localfile>` ブロックを `</ossec_config>` の外側に追加した可能性が高かった。

対応として、追加した `<localfile>` ブロックの位置を確認し、必ず `</ossec_config>` より前に配置するよう修正した。

正しい例は以下である。

```xml
<localfile>
  <log_format>json</log_format>
  <location>/var/lib/docker/containers/xxxxxx31-json.log</location>
</localfile>
```

修正後、Wazuh Agentは正常に再起動できた。

## 5. ハニーポットログ収集の確認

### 5.1 VPS2：Dionaea Webハニーポット

VPS2では、DockerコンテナとしてDionaea Webハニーポットが稼働していた。

```text
CONTAINER ID   IMAGE                      PORTS
80822f96e02b   dinotools/dionaea:latest   0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp
```

公開ポートは以下である。

```text
80/tcp
443/tcp
```

Dionaeaの実ログはDocker JSONログに出力されていた。

```text
/var/lib/docker/containers/xxxxxx29-json.log
```

このログをWazuh Agentの監視対象に追加した。

```xml
<localfile>
  <log_format>json</log_format>
  <location>/var/lib/docker/containers/xxxxxx29-json.log</location>
</localfile>
```

Wazuh Agentのログでは、以下のように監視開始を確認した。

```text
Analyzing file: '/var/lib/docker/containers/xxxxxxxxxx29-json.log'
```

### 5.2 VPS3：Dionaea DBハニーポット

VPS3では、DockerコンテナとしてDionaea DBハニーポットが稼働していた。

```text
NAMES        IMAGE                      PORTS
dionaea-db   dinotools/dionaea:latest   0.0.0.0:1433->1433/tcp, 0.0.0.0:3306->3306/tcp
```

公開ポートは以下である。

```text
1433/tcp
3306/tcp
```

Dockerログには、MySQL系の反応ログが出力されていた。

```text
mysqld /dionaea/mysql/mysql.py
DATABASE opening information_schema
DATABASE opening b'mysql_native_password'
```

VPS3のDocker JSONログパスは以下である。

```text
/var/lib/docker/containers/xxxxxx31-json.log
```

このログをWazuh Agentの監視対象に追加し、Agentが正常に監視を開始することを確認した。

### 5.3 VPS4：IoTハニーポット

VPS4についても、VPS2・VPS3と同様にWazuh AgentをManagerへ接続し、Agent状態が `Active` であることを確認した。

IoTハニーポットについては、Dockerコンテナの起動状態、待受ポート、Docker JSONログのパスを確認し、Wazuh Agentの `<localfile>` に追加する方針とした。

確認項目は以下である。

```bash
hostname
sudo docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Ports}}"
sudo ss -lntup | grep -E '(:22|:23|:2323|:2222|:8080|:80|:443)'
sudo docker inspect --format='{{.LogPath}}' <コンテナ名>
sudo grep -F "Analyzing file" /var/ossec/logs/ossec.log | tail -n 20
```

## 6. ログ肥大化対策

VPS3でDionaeaログが34GBまで肥大化したため、各VPSでDockerログのローテーション設定を行った。

`/etc/docker/daemon.json` に以下を設定した。

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "5"
  }
}
```

設定後、Dockerを再起動した。

```bash
sudo systemctl restart docker
```

その後、コンテナが再起動後も稼働していることを確認した。

```bash
sudo docker ps
```

これにより、Dockerログが無制限に肥大化することを防止できるようになった。
