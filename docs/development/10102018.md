# UbuntuDesktop 隔離バックエンド構築レポート(10/8 13:00 - 10/10 20:00)

## 概要
VPS1 の Cowrie Proxy が接続する隔離バックエンドを、UbuntuDesktop上のlibvirt 仮想マシンとして構築した。バックエンドで発生するログは、生ログを外部へ直接送らず、必要な特徴量だけを残した正規化NDJSONに正規化してLinuxWSのWazuh Managerへ集約する構成とした。

## 実施した構築

- UbuntuDesktop に QEMU/KVM、libvirt、cloud-init 関連ツールを導入した。
- インターネットへ転送しない libvirt ネットワーク `autosoc-isolated` を作成した。
- Ubuntu Server の公式 cloud image から `autosoc-backend` VM を作成した。
- VM に固定のプライベートIPを割り当て、ホストからのみ SSH 接続できるようにした。
- VM の UFW を受信・送信とも原則拒否とし、DHCP、ホストDNS、ホストへの TCP 6514 ログ転送だけを許可した。
- VM の rsyslog から、ホストの rsyslog receiver へ TCP 6514 でログを転送する経路を作成した。
- ホスト側で受信ログをローテーションし、Wazuh Agent が読める権限で保存するようにした。
- 正規化プログラム `autosoc-backend-normalize-v1` と15秒間隔の systemd timer を導入した。
- LinuxWS に backend 用 Wazuh ルールと schema validator の許可リストを追加した。

## 接続制限について

- VM はインターネットへのデフォルトルートを持たない。
- VM のログ転送先は隔離ネットワーク上のホストに限定した。
- canonicalイベントには生のメッセージ、コマンド、パスワードを格納しない。
- 生ログはホスト内にのみ保存し、LinuxWS へは canonicalログだけを送信する。
- Wazuh の許可ルールは、backend.syslog と ubuntu-desktop-backendに限定した。

## 動作確認

制御ログを隔離VMで発生させ、以下を確認した。

- VMからホストへのログ転送
- canonical NDJSONへの変換
- Wazuh Agent 005 から LinuxWS への送信
- Wazuh ルール `100611` の検証
- schema validator の **valid-events.ndjson** への保存
- event gate の **controlled-test-events.ndjson** への隔離

以上により、隔離バックエンドのログ収集経路は完成した。
