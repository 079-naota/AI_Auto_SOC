# VPS3の動作確認と通信確認（10/7 10:30-11:30）
VPS3は、DionaeaDBのハニーポットとしてMySQLおよびMSSQL系の攻撃観測を担当する構成にした。

## 現状
第一段階では、Docker上でDionaea DBが稼働していて、1443・3306ポートをしていた。

WazuhAgentも稼働していて、旧VPS1にログを送信していた。

## 調査結果
Dockerに関しては第一段階通り、dionaea-dbコンテナが稼働していた。

一方で、既存のWazuh設定には古いDockerコンテナIDを指定していたログパスが残っていた。

そのため、現在のDionaeaDBテーブルを正しく収集できなかった。

## 修正
調査結果より、SQliteDB **/dionaea/data/dionaea.sqlite** を入力元とする正規化機能を新しく構築した。対象とした主なDionaeaDBテーブルは以下である。
- connections
- logins
- mysql_commands
- mssql_commands

構築したexporterは以下に配置した。
- /libexec/autosoc-db-exporter.py

出力先は以下に設定した。
- /log/autosoc/db-events.ndjson

出力されるイベントでは、パスワードやコマンド本文などをそのまま出力せず、ハッシュとバイト数として記録するよう設計した。
これは、分析に必要な特徴量を残しつつ、生データの露出を抑制するためである。

timerも作成し、初回起動時にAgentのbufferが一時的に圧迫されたので、最終的にバッチサイズを100、5分間隔の安全な運用設定へ調整した。

LinuxWSでは。VPS3DB用のWazuhルールを追加した。
- 100500:db.connections
- 100501:db.login
- 100502:db.mysql
- 100503:db.mssql

ログテストにより、各データセットが対応するルールに正しく一致することを確認した。その後接続検証を行い、以下の経路を確認した。

- db.connectionsはvalid-events.ndjsonを通過後、unclassified-events.ndjsonへ
- db.loginはvalid-events.ndjsonを通過後、analysis-candidates.ndjsonへ

## まとめ
以上によりVPS3について以下の経路を正常に成立した。

**Dionaea DB SQLite → canonical NDJSON → Wazuh Agent → LinuxWS Wazuh Manager → schema validation → event gate**
