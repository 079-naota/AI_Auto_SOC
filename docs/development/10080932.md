# VPS4の再構築（10/08 0:00-2:30）

VPS4のDionaea IoTハニーポットについて、既存環境を確かめたうえで、SQLiteデータベースを入力元とするログ収集経路を構築した。

## 作業内容
主な作業内容は以下のとおりである。

- VPS4のOS、Docker、Dionaea、Suricata、Wazuh Agent、ネットワーク設定を調査
- DionaeaのSQLiteデータベースを安全な入力元として選定
- 接続情報から認証情報を除外し、NDJSONへ変換するnormalizerを構築
- 差分処理用のstate管理を導入し、過去ログの大量再送を防止
- 最小権限ユーザーでnormalizerを実行する構成を設定
- systemd service・timerによる定期実行を設定
- Wazuh Agentにcanonicalログのみを追加監視
- LinuxWSにVPS4 Dionaea IoT用のWazuhルールを追加
- schema validatorおよびevent gateを通過することを確認

## 実装後検査結果
検証の結果、Dionaeaの実イベントが以下の経路を通過することを確認した。

**Dionaea SQLite→ canonical NDJSON→ Wazuh Agent→ LinuxWS Wazuh Manager→ schema validation→ event gate→ analysis-candidates**

不正なJson、event_id重複、schema検査、routing errorは発生しなかった。既存のVPS4 Suricata経路は、新しいDionaea経路の安定性を確認するため維持している。
