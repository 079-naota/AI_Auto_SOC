# 各VPSの容量問題について(11/6)

## 現状
各VPSは収集したログを全て本体SSDに格納している。
特に、収集する項目の多いハニーポットを運用しているVPSは数日の収集でSSDを使い切ってしまう。
Backendを担当しているVPSが最も圧迫している例である。

## 対処法
現状に対する対処法として、送信済みログについては古いものから順に削除していく手段を考案する。
そこで、削除するログに関しては以下のルールを採用する。
- 送信から72時間(3日)がたったもの
- WSにおいて保存が確認されたもの
- 処理中以外のもの

## WS送信の信頼性確保について
対処法の削除条件で触れたようにWSへの到達を確認できたか否かが削除許可への重要な部分になる。
そこで、送信・到達の信頼性を確保するには、以下の処理を行うことが重要と考える。

- アップロード前と済みでディレクトリを分ける
- 送信するデータのハッシュ値を用いてデータの完全性を担保する（実装済み）
- 送信が終了した際にお互いのハッシュ値を送信し、一致した場合のみアップロード済みへ移動する

これにより、アップロード済みに入ったログから72時間が経過したものを削除し、圧迫問題を解決できると考える。
